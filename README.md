# CX Pain Map: NPS + CRM

Единый Streamlit MVP для анализа клиентской боли из двух источников:

- **NPS / CX**: оценки, сегменты, вопросы, комментарии.
- **CRM**: обращения, статусы, каналы, категории, ответственные блоки.

Цель версии: быстро проверить механику на реальных файлах без LLM-зависимости.

## Что умеет

1. Загружает `xlsx`, `xls`, `csv`.
2. Даёт ручной маппинг колонок.
3. Нормализует NPS и CRM к единой схеме.
4. Тегирует боли по словарю паттернов.
5. Строит:
   - динамику по дням/неделям/месяцам;
   - топ болей;
   - карты `клиника × боль`, `канал × боль`, `ответственный блок × боль`;
   - общий слой NPS + CRM;
   - evidence-примеры.
6. Выгружает Excel:
   - `feedback_tagged`;
   - `feedback_exploded`;
   - `topic_summary`;
   - `clinic_topic`;
   - `monthly`.

## Запуск локально

```bash
pip install -r requirements.txt
streamlit run app.py
```

## Быстрый тест

По умолчанию включён демо-режим. Его можно отключить в сайдбаре и загрузить реальные файлы.

## Минимальные обязательные поля

### NPS/CX

- дата;
- текст / комментарий.

Опционально:

- клиника;
- сегмент;
- оценка;
- вопрос;
- опция ответа.

### CRM

- дата обращения;
- текст обращения.

Опционально:

- клиника;
- канал;
- статус;
- категория;
- ответственный блок.

## Как расширять

Таксономия болей лежит в `PAIN_TAXONOMY` внутри `app.py`.
Для первого теста это нормально. После проверки на боевых данных лучше вынести её в `pain_taxonomy.yaml`.

## Следующий слой

После проверки механики можно добавить:

- словарь с весами паттернов;
- fuzzy matching;
- ML-классификатор;
- LLM root-cause блок;
- сравнение NPS-боли и CRM-боли по периодам;
- отдельный операционный отчёт для директора.
